**Сервис оценки рыночной стоимости подержанных автомобилей на основе машинного обучения.**

Проект охватывает полный цикл: объявления drom.ru → очистка и исследование данных → CatBoost → Streamlit-приложение с необязательным ИИ-автозаполнением и SHAP-объяснением цены.

- **Данные:** 585 855 объявлений за январь–июль 2025 года.
- **Модель:** CatBoost + `TransformedTargetRegressor(log1p)`, 23 признака.
- **Качество:** TEST MAPE **15.40 %**, MAE **142 920 ₽** на отложенной выборке.
- **Интерфейс:** Streamlit, GigaChat-2, Plotly, SHAP.
- **Запуск:** локально на Python 3.11 или в Docker.

> Публичный демо-стенд сейчас не поддерживается. Актуальный способ запуска — локально или через Docker (см. раздел [«Запуск»](#-запуск)).

## ✨ Возможности

- **🤖 Автозаполнение формы через ИИ** — опишите автомобиль своими словами, и GigaChat-2 извлечёт параметры в структурированный JSON. Поля, которые заполнил ИИ, отмечаются значком ✨.
- **📈 Прогноз цены** — CatBoost, обученный на оптимизированном датасете, оценивает стоимость по 20 полям формы, которые превращаются в 23 признака модели.
- **🔍 Проверка цены объявления** — приложение предупреждает, если введённая цена ниже или выше рассчитанного диапазона.
- **📊 SHAP-интерпретация** — интерактивный waterfall по категориям факторов: пробег и износ, двигатель, история, бренд, кузов, география. Вклады пересчитываются в рубли.
- **⚠️ Предупреждения о границах применимости** — для автомобилей старше 1990 года и пробега больше 999 999 км интерфейс предупреждает о менее надёжном прогнозе.
- **🐳 Docker** — образ содержит приложение и модель; данные и ноутбуки для инференса не нужны.

## 🎯 Как пользоваться

1. **Опишите автомобиль своими словами** — чем больше деталей, тем точнее. Например:
   > «Продаю ладу гранту 15 года, 2 владельца, пробег 40к, механика, 106 сил»
2. Нажмите **«Распарсить через ИИ»**. Если ключа нет, заполните форму вручную.
3. **Проверьте поля**, отмеченные ✨, и исправьте ошибки ИИ.
4. При необходимости укажите **цену из объявления** — приложение сравнит её с рассчитанным диапазоном.
5. Нажмите **«Рассчитать цену и влияние факторов»**:
   - получите рекомендованную цену и верхнюю поправку (погрешность в рублях и процентах);
   - увидите предупреждение, если цена объявления сильно ниже или выше рассчитанного диапазона;
   - изучите waterfall и детальный разбор вкладов в рублях.

### Про диапазон цены

Диапазон в приложении **не симметричный** и не является статистическим доверительным интервалом. Используется эвристика на основе MAPE:

```text
lower = price × (1 − 2 × 0.1539)
upper = price × (1 + 0.1539)
```

То есть нижняя граница шире верхней. В интерфейсе метрика показывает только верхнюю поправку (`+ … ₽` и процент MAPE), а нижняя граница используется для проверки цены объявления и отдельно не выводится. Сам диапазон всегда считается по формуле выше.

### Про дату размещения

Модель обучена на объявлениях января–июля 2025 года. Для признака `Год размещения` лучше указывать реальную дату публикации. Если дата выходит далеко за пределы обучающего периода, прогноз становится менее надёжным.

## 🧠 Как устроена модель

### 1. Очистка данных — `notebooks/01_data_cleaning.ipynb`

- фильтрация периода `2025-01-14`–`2025-07-14`;
- удаление колонок, где больше 50 % пропусков;
- удаление строк без пробега и дубликатов;
- исключение автомобилей до 1990 года;
- фильтрация объёма двигателя (0 для электромобилей или 0.6–6.8 л) и мощности (≤ 800 л.с.);
- замена пробега `999 999 км` медианой по году;
- заполнение пропусков по `Название машины`/году на основе train;
- split 80/20 (`random_state=42`);
- сохранение `df_optimal.parquet` и очищенных train/test.

### 2. EDA и признаки — `notebooks/02_eda_and_features.ipynb`

- анализ распределения цены и корреляций через **Phik**;
- логарифмирование целевой переменной `log1p`;
- экспериментальные преобразования `Пробег`/`Мощность` и бизнес-признаки;
- `Модель`, `Класс бренда` (Люкс / Премиум / Эконом / Масс-маркет), `Литровая мощность`, `Пробег за год`, `Тип продавца`, `Год размещения`;
- сохранение `features`-датасета для сравнения. В финальную модель эта ветка не пошла: `cleaned` и `features` показали худший TEST MAPE — вероятно, из-за агрессивной очистки и заполнения пропусков, а в `features` ещё и из-за логарифмирования признаков.

### 3. Финальный пайплайн — `notebooks/03_final_catboost_optimized.ipynb`

- минимальная очистка `df_optimal.parquet`, включая фильтр `Цена ≥ 150 000 ₽`;
- генерация признаков и использование `Комплектация` + `Особые отметки` как текстовых признаков;
- нативная обработка категорий CatBoost;
- логарифмирование таргета через `TransformedTargetRegressor`;
- 5-fold CV, seed 42;
- обучение на GPU (`task_type='GPU'`);
- сохранение `models/best_catboost_model.pkl` и `data/optimized/*.parquet`.

### Финальная модель

```python
CatBoostRegressor(
    bootstrap_type='Bernoulli',
    iterations=2500,
    learning_rate=0.042248138023520114,
    depth=10,
    l2_leaf_reg=9.394802632887766,
    random_strength=0.8303775333704183,
    border_count=207,
    subsample=0.5483853226992782,
    loss_function='MAE',
    eval_metric='MAE',
    random_seed=42,
    thread_count=-1,
    task_type='GPU',          # только обучение
    verbose=0,
)
```

Модель обёрнута в:

```python
TransformedTargetRegressor(
    regressor=catboost_model,
    func=np.log1p,
    inverse_func=np.expm1,
)
```

В модели **23 признака**: 13 категориальных, 2 текстовых (`Комплектация`, `Особые отметки`) и 8 числовых. Гиперпараметры были найдены Optuna в экспериментах; финальный ноутбук использует уже зафиксированные значения. Для инференса GPU не нужен — приложение работает на CPU.

**Почему loss = MAE, а метрика — MAPE?** Модель учится на `log1p(цена)`. Для небольших ошибок:

```text
|ln(ŷ) − ln(y)| = |ln(1 + (ŷ − y) / y)| ≈ |(ŷ − y) / y|
```

Поэтому MAE на логарифмах хорошо приближает относительную ошибку, из которой считается MAPE. Это не делает MAPE и MAE одной и той же метрикой, но объясняет выбор функции потерь.

### Константа диапазона

В `src/predict.py` зафиксировано:

```python
MODEL_MAPE = 0.1539
```

Это значение близко к тестовой оценке финального артефакта (15.40 %) и используется для эвристического диапазона. Оно не пересчитывается на каждом запросе и не является доверительным интервалом.

## 📈 Результаты

### Финальная модель

Метрики финального `models/best_catboost_model.pkl` на отложенной выборке:

| Метрика | Значение |
|---------|----------|
| CV MAPE (5-fold) | **15.55 %** |
| CV MAE | **147 461 ₽** |
| **TEST MAPE** | **15.40 %** |
| **TEST MAE** | **142 920 ₽** |
| MAPE на авто дешевле 300 тыс. ₽ | **23.68 %** |
| MAPE на остальных (≥ 300 тыс. ₽) | **13.79 %** |

Метрики получены на одном случайном split; внешней или временной валидации нет. Дешёвый сегмент предсказывается заметно хуже: там выше относительный разброс и сильнее влияют состояние, история и юридические факторы, которых нет в данных.

### Сравнение датасетов

Исследование `researches/01_datasets_comparison.ipynb`, одна и та же CatBoost-конфигурация:

| Датасет | CV MAPE | TEST MAPE | TEST MAE |
|---------|---------|-----------|----------|
| `raw` | 15.69 % | 15.48 % | 121 015 ₽ |
| `cleaned` | 18.05 % | 18.36 % | 139 507 ₽ |
| `features` | 18.08 % | 18.44 % | 141 096 ₽ |
| **`optimized`** | **15.45 %** | **15.29 %** | **139 173 ₽** |

**Главный вывод:** лучший TEST MAPE — у `optimized`, а не у «максимально очищенного» `cleaned` или `features`. `raw` близок по MAPE, но содержит больше шума и меньше бизнес-признаков. Агрессивное заполнение пропусков и логарифмирование признаков в `cleaned`/`features` ухудшили результат: CatBoost сам умеет работать с NaN и категориями.

Разница между `15.29 %` в исследовании и `15.40 %` у финального артефакта объясняется разными прогонами и набором текстовых признаков: в research-сравнении использовалась прежде всего `Комплектация`, а в финальном ноутбуке добавлены `Комплектация` и `Особые отметки`. Для приложения используется артефакт из `03_final_catboost_optimized.ipynb` и константа `0.1539`.

Дополнительная проверка на одной машине (Kia Rio 2021, цена 1 800 000 ₽) в research 01:

| Датасет | Прогноз | Ошибка |
|---------|---------|--------|
| `raw` | 1 017 032 ₽ | 43.5 % |
| `features` | 3 685 881 ₽ | 104.8 % |
| `optimized` | 2 040 461 ₽ | **13.4 %** |

Это единичный пример, а не метрика качества, но он показывает, почему средний MAPE сам по себе недостаточен.

## 🔬 Интерпретируемость

### SHAP

![Глобальные SHAP-эффекты](images/shap_beeswarm_summary.png)

Главные драйверы цены в модели — **комплектация, год, мощность, объём двигателя и пробег**. Пробег в среднем снижает цену, а более новый год, мощность и богатая комплектация — повышают.

В приложении SHAP-вклады пересчитываются из логарифмов в рубли и группируются по категориям:

![SHAP-разбор по категориям факторов](images/streamlit_shap_category_analysis.png)

Примеры waterfall для недорогого и дорогого автомобиля: [низкая цена](images/shap_waterfall_low_price.png), [высокая цена](images/shap_waterfall_high_price.png).

> SHAP-вклады — это условные объяснения модели на конкретных данных, а не строгие причинные эффекты. Они не доказывают, что, например, «комплектация причинно добавляет ровно X рублей».

### PDP / ICE

![PDP/ICE для года, пробега и мощности](images/pdp_ice_year_mileage_power.png)

По `researches/02_ice_pdp_analysis.ipynb`:

- **Год:** чем новее автомобиль, тем выше цена; после 2010–2015 годов рост заметнее.
- **Пробег:** средняя цена снижается с ростом пробега; индивидуальные ICE-кривые различаются.
- **Мощность:** основной рост примерно до 150–160 л.с., затем кривая становится более пологой. Ступеньки — следствие разбиения деревьев, а не отдельный «налоговый порог».

PDP/ICE — sanity-check направления зависимостей, а не оценка качества модели.

### Анализ ошибок

`researches/04_error_analysis.ipynb`:

- для автомобилей старше 10 лет MAPE **16.81 %**, для свежих 0–3 лет — **10.18 %**;
- в верхнем ценовом сегменте модель в среднем занижает цену: `mean_bias` около **+95 800 ₽**;
- топ-50 ошибок содержит объявления с подозрительно низкими ценами; относительная ошибка там доходит до сотен процентов. Это скорее шум/аномалии в объявлениях, чем типичная ошибка модели;
- по финальной модели дешёвые авто (<300 тыс. ₽) дают MAPE **23.68 %**, остальные — **13.79 %**.

Основные причины ошибок: отсутствие признаков реального состояния, истории обслуживания и юридической чистоты; дисбаланс выборки; шум в целевой переменной.

## ⚠️ Ограничения

- Модель обучена на объявлениях **января–июля 2025 года**; это не универсальный оценщик для любого региона и времени.
- Используется один случайный train/test split. Внешняя и временная валидация не проводились, поэтому метрики могут быть оптимистичными.
- Нет фотографий, VIN-истории, данных об авариях, обслуживании и реальном состоянии автомобиля. Год и пробег — лишь приблизительные прокси износа.
- Дешёвые автомобили и машины старше 10 лет предсказываются хуже.
- Модель не является заменой осмотру, диагностике и юридической проверке. Прогноз — ориентир, а не гарантированная цена сделки.
- Диапазон цены — эвристика на основе MAPE, а не доверительный интервал.
- GigaChat может ошибаться в извлечении параметров; поля нужно проверять вручную. Для ИИ нужен действующий ключ с доступом к `GIGACHAT_API_PERS`.
- Обучение требует исходного CSV, которого нет в репозитории, и GPU для финального ноутбука. Инференс работает на CPU без данных.

## 🔁 Обучение с нуля

### 1. Подготовьте данные

Положите исходный CSV:

```text
data/raw/raw_dataset.csv
```

Ноутбуки ожидают такую структуру:

```text
data/
├── raw/
│   ├── raw_dataset.csv
│   └── df_optimal.parquet          # создаёт 01
├── cleaned/
│   ├── train_cleaned.parquet
│   └── test_cleaned.parquet
├── features/
│   ├── train_features.parquet
│   └── test_features.parquet
└── optimized/
    ├── train_optimized.parquet
    └── test_optimized.parquet
```

### 2. Установите зависимости для ноутбуков

```bash
pip install -r requirements.txt
pip install jupyterlab shap
```

`shap` нужен только для `researches/03_shap_interpretation.ipynb`; в runtime-зависимости приложения он не входит.

### 3. Запустите ноутбуки по порядку

Рабочая директория — `notebooks/`, потому что внутри используются пути вида `../data/...`:

| Ноутбук | Вход | Выход |
|---------|------|-------|
| `01_data_cleaning.ipynb` | `data/raw/raw_dataset.csv` | `data/raw/df_optimal.parquet`, `data/cleaned/*` |
| `02_eda_and_features.ipynb` | `data/cleaned/*` | `data/features/*` (эксперимент) |
| `03_final_catboost_optimized.ipynb` | `data/raw/df_optimal.parquet` | `models/best_catboost_model.pkl`, `data/optimized/*` |

```bash
cd notebooks
jupyter lab
```

Ноутбук `03` перезаписывает `models/best_catboost_model.pkl`; перед запуском сделайте резервную копию, если модель уже используется. Для обучения нужен GPU: в параметрах стоит `task_type='GPU'`. Для CPU замените на `task_type='CPU'` — обучение будет заметно медленнее.

### 4. Исследования

Ноутбуки в `researches/` запускаются из своей директории и читают `../data/optimized/*` и `../models/best_catboost_model.pkl`:

```bash
cd researches
jupyter lab
```

`01_datasets_comparison.ipynb` сравнивает все четыре датасета; `02`–`04` строят PDP/ICE, SHAP и анализ ошибок. Они требуют подготовленных данных и обученной модели.

### 5. Экспериментальные скрипты

`models/01_compare_defaults.py`, `02_hpo_comparison.py` и `03_final_compare.py` — исторические эксперименты, а не обязательная часть запуска приложения. Они предполагают `data/features/*`, запуск из директории `models/` и содержат локальный абсолютный путь MLflow (`C:/project/...`). Часть экспериментов рассчитана на GPU: CatBoost с `task_type='GPU'`, XGBoost с `device='cuda:1'`. Для воспроизведения на другой машине путь MLflow и GPU-параметры нужно заменить. Основной воспроизводимый пайплайн — ноутбуки, прежде всего `03`.

MLflow-база и артефакты локальные и исключены из Git; для приложения они не нужны.
